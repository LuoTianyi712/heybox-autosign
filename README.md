# 小黑盒自动签到 App

安卓 App，每天定时自动完成小黑盒（Heybox）的每日签到和分享任务（默认凌晨 00:30，App 里可改），锁屏黑屏状态下照常运行，运行结束在通知栏显示结果。

## 界面结构

- **主页（仪表盘）**：今日任务完成度与进度条、H币/盒电、等级（Lv）与经验、上次/下次执行时间、一键「立即运行一次」；下方依次是账号列表、任务清单、执行设置（执行时间/分享开关/备用服务器）、权限（电池优化豁免/精确闹钟开关，实际授权需在系统弹窗里确认）。
- **账号页**：当前账号以列表展示（多账号时逐行显示），每个账号可「检查」登录态与接口有效性、可「删除」；下方是手机验证码登录、Cookie 查看与编辑。
- **运行日志页**：只展示本次运行的过程与失败项原始数据，右上角一键复制完整日志。
- **设置页（右上角齿轮）**：运行日志入口与版本信息。

主页信息默认不自动刷新，点右上角 ⟳ 手动刷新；打开 App（含从后台切回）和每次任务执行结束后会自动刷新一次（后台闹钟跑完也会通过应用内广播触发）。

## 产物

`F:\AutoSignIn\小黑盒自动签到.apk` —— 直接传到手机安装（约 60KB，无广告、无第三方依赖）。

## 工作原理

App 内置了小黑盒接口的签名算法（从开源逆向项目移植并验证），用登录 Cookie 直接调用小黑盒官方接口完成任务。数据只保存在你手机本地，只和小黑盒官方服务器通信。唯一例外：如果分享任务的"本地分享上报"没有结算成功，可以在主页打开「分享失败时用备用服务器」，打开后社区搭建的 hkey 签名服务器（hkey.qcciii.com）会收到你的好友 ID（heybox_id）和设备号（imei），但**永远不包含你的 Cookie 或密码**。

支持的任务：每日签到、分享帖子、分享游戏详情、分享游戏评价。其他类型的每日任务（如浏览停留）会记录在日志的"运行过程"里。

账号支持两种登录态：**可签到登录态**（官方 App 接口签发的 `pkey`，实测标记 `48`/`88` 都能签到，其余任务也全部可用）和**网页登录态**（标记 `28`，只能拉任务和做分享，签到会被拒绝）。粘贴时一行一个：`pkey=...`。

账号页的「检查」会对账号发一次带签名的任务列表请求：能正常取回账号信息即判定「有效」；返回登录失效则为「已失效」；签名/网络/服务器异常显示「接口异常」，用来快速区分 Cookie 过期还是接口本身出问题。

## 登录（手机内短信验证码）

1. 主页点「账号」→「手机验证码登录」。
2. 输入手机号 → 点「获取验证码」（会弹出腾讯滑块，拖一下）。
3. 收到短信后填验证码 → 点「登录」。成功后自动保存登录态并返回。

登录会**优先走官方 App 的接口参数**（hkey + mobile 签名 + 设备 token），拿到的 `pkey` 实测可直接签到；万一 App 通道不可用会自动回退到网页接口（此时只能拉任务/分享，登录后会有提示）。

也可以粘贴登录态。**签到必须用 App 通道的 pkey**：

- 直接粘贴 `pkey=MTc5...` 一行即可（`88`/`48` 标记都能签到）。
- 兜底办法：在已登录官方 App 的 root 设备/模拟器上读取 `files/mmkv/account`，取出 `"pkey":"..."` 粘贴。
- 网页 Cookie（电脑 Chrome 打开 https://www.xiaoheihe.cn/ 登录后复制）：只能拉取和分享，签到会被拒绝。

> 旧版的"网页登录"因 WebView 第三方 Cookie 策略拿不到 pkey，已移除，仅保留短信登录。

## 使用流程

1. 把 APK 传到手机，点击安装，允许"安装未知来源应用"。
2. 打开 App →「账号」页登录（或粘贴 Cookie）。
3. 回主页点「立即运行一次」，等约 30~60 秒；完成后主页会自动刷新，可在右上角齿轮 →「运行日志」查看过程。
4. 主页「执行」区可改执行时间、按需打开分享任务；「权限」区点「电池优化豁免」和「精确闹钟权限」（安卓 12+）各授权一次。
5. 各品牌手机建议再手动开启"后台自启动/锁定后台"（如 MIUI：最近任务下拉锁定；ColorOS/OriginOS：设置→电池→后台高耗电允许），防止夜间被杀后台。

定时规则：每天在设定时间触发；如果当天执行失败（断网/服务器异常），会在 1 小时后自动重试，最多 5 次；成功或重试次数用完后，自动排到次日的设定时间。已经签到过的情况下 App 只查询状态，不会重复签到。手机重启后会自动恢复定时。

## 已知问题

- **签到接口要求 App 登录态**：小黑盒只接受官方 App 通道签发的 `pkey`（网页登录的 `28` 态返回 `relogin`/`非法的请求`）。本 App 的短信登录已改为优先走 App 接口参数，正常能直接拿到可签到的 `pkey`；若被回退成网页登录态，登录成功提示里会说明，可改用粘贴 pkey 的方式。可签到登录态下签到、快照、分享全部走 App 签名接口。
- 「分享评论到社交平台」任务：评论分享事件已按多种格式上报，服务器接受但任务状态可能延迟结算（+10 经验的小任务），日志会显示"已上报，服务器结算可能延迟"；其余任务正常。
- 主页任务清单显示的是**本次执行结束后**的服务器状态；若某任务服务器延迟结算，下次刷新/执行才会更新。

## Cookie 过期

Cookie 一般能维持数周到数月。失效的表现是日志显示"登录校验未通过"，此时到「账号」页重新登录一次即可。App 每天只上报一次执行结果，不会频繁登录。

## 风险提示

这是个人自用的自动化工具，请勿泄露 Cookie 给他人。使用第三方接口调用属于灰色地带，理论上存在账号风控风险，请自行斟酌（本项目只做官方 App 本来就会发的请求）。

## 重新构建

源码在 `heybox-app\src`，构建脚本 `heybox-app\build.ps1`（需要 JDK 与 `tools\` 下的安卓构建工具链，已就绪）。签名密钥不入库（`appkey.jks` 已在 `.gitignore`）；构建脚本从 `heybox-app\keystore.pass`（一行密码，不入库）或环境变量 `XHH_KS_PASS` 读取签名密码，自建正式包请用自己的 keystore，更新时须用同一密钥签名，否则手机上无法覆盖安装。
